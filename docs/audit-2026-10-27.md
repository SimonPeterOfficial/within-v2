Audit-first mission. No code was modified, no database was migrated or seeded, no work was discarded.

## A. Executive Summary

WITHIN is a Next.js 16 (canary) App Router monolith with a real Neon Postgres database, a dual
(legacy + Clerk) authentication architecture, a large in-house visual design system, and a real
content/messaging/communities backend. The baseline is healthy where it counts:

- TypeScript clean, lint clean (5 warnings), production build succeeds, smoke test passes,
  DB reachable, all 27 tables present, auth gates behave correctly at runtime.

But the release is **not** ready. The decisive blocking findings:

1. **Clerk integration is inert end-to-end.** Not configured (no keys), `clerkMiddleware()` never
   mounted, `users.clerk_id` missing from the live DB, and only 7/9 migrations applied. Three
   independent layers of the same feature are stubbed; the middleware's manual `verifyToken` gate
   is the only Clerk-aware piece that would even run.
2. **Confirmed hydration defect on `/atlas`** (React #418) in the production build: clock-derived
   text rendered during hydration can never match prerendered static HTML.
3. **Large swaths of finished functionality are orphaned**: Mirror, Connections, While-You-Were-Away,
   World/Pulse, WithinExperience — real UIs against real APIs, never routed.
4. **Admin suite is mock-data shells** (except overview + login). Releasing admin with fabricated
   user/content/moderation data violates Product Law 1 (truth over magic).
5. **Deployed DB is behind the repository schema** — `users.clerk_id` absent, password columns still
   NOT NULL. Clerk-only account creation would fail with 500s if wired up today.
6. **Dev scripts and the app share one database** (`DATABASE_URL` identical in `.env.local` and
   `.env.development.local`; 23 users already exist there). `npm run seed:dev` would write into the
   same DB the production app reads.

The architecture itself is.sound — one schema, honest API authorization, truthful state handling.
The work is wiring, truth-restoration, and one migration — not redesign.

From here on: **P0** = blocks correct behavior/release; **P1** = functional gap or confirmed defect;
**P2** = quality/risk; **P3** = polish.

## F. Authentication and Authorization

   `within-session` cookie (`lib/auth/session-token.ts`, Web Crypto edge-safe), 30-day expiry,
   DB re-check on every read (`lib/auth/server.ts::getSessionUser` rejects suspended/deleted).
   Dev fallback secret only when `NODE_ENV !== "production"` (hard error otherwise).
2. **Clerk (committed but not configured):** `ClerkProvider` when
   `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` present (layout.tsx L113–135); server resolution
   `lib/auth/clerk.ts` (`currentClerkUserId` → `resolveClerkUser`); account linking
   `/account-link` + `/api/auth/clerk/link` (server-verified legacy password → link);
   webhook `api/webhooks/clerk` (svix-verified, idempotent, honest email-conflict handling).

## K. Confirmed Bugs and Their Evidence

### K-1 [C] P0 — Hydration text mismatch (#418) on `/atlas` in production
- **Evidence:** Playwright run against `npm run build` + `next start`: `PAGEERROR …/atlas: Minified
  React error #418` (server text ≠ client text). No other route threw it.
- **Root cause:** `lib/atlas/useAtlasTime.ts` — shared minute clock via
  `useSyncExternalStore(subscribe, floorToMinute, getServerTime)`. `getServerTime()` calls
  `floorToMinute()` → the **client's current minute**, which can never equal the minute baked into
  statically-prerendered HTML (`/atlas` is ○ static). `StarClock.tsx` L40–46 renders sidereal
  **H:MM:SS digits** from that clock during the hydration render → text differs from build-time text
  → #418 → client-side regeneration (visible slow-render/jank on every visit).
- **Why only /atlas:** StarClock's second-precision digits are the only clock-text that *must* differ
  between two arbitrary minutes; TopBar's slowly-varying sky chip and constellation names coincide
  in practice within a browser-view window.
- **Expected:** hydration-safe instruments — identical first render server/client.
- **Correction:** render a deterministic placeholder (`"···"` text node or `min-w` no-op) for all
  clock-derived *text* until the first post-mount tick (extend the `useMountedSafe` pattern the
  stability mission already introduced for StarClock's local time, MoodLab, TimeRift), OR make the
  sidereal readout minute-floored-neutral on first render. Then re-run `.verify-routes.mjs`
  expecting 0 PAGEERROR.
- **Risk:** low; localized to atlas instruments; re-enable the cinematic loader only after this +
  the Footer/HomeDock fabrications are fixed.
